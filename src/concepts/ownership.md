# 所有权与借用 (Ownership & Borrowing)

这是 Rust 最独特、最困难，也是最迷人的部分。它是 Rust 能够在其不需要垃圾回收 (GC) 的情况下保证内存安全的核心机制。

## 1. 核心哲学：资源管理的责任制

在大多数语言中，资源的清理要么靠手动（C/C++），要么靠后台默默工作的清洁工（Java/Go 的 GC）。
Rust 引入了**“单一所有权” (Single Ownership)** 原则：

> **RULE**: 任何时刻，内存中的每一个值都有且只有一个变量作为它的 **所有者 (Owner)**。

### 词源学解构
- **Owner (所有者)**: 拥有物品合法支配权的人。在 Rust 中，变量就是数据的“主人”。
- **Scope (作用域)**: 权力的边界。一旦主人离开了它的权力范围（离开作用域），它所拥有的东西就会被立即销毁。

## 2. RAII：资源获取即初始化

Rust 的内存管理深深植根于 C++ 的 **RAII (Resource Acquisition Is Initialization)** 思想，并将其强制化。

- **申请 (Allocation)**: 当你创建一个变量（如 `let s = String::from("hello")`），内存被申请。
- **释放 (Deallocation)**: 当变量 `s` 离开作用域（`}`），Rust 自动调用 `drop` 函数释放内存。

你不需要写 `free(s)`，Rust 编译器在编译阶段就帮你插入了这段代码。

## 3. 移动 (Move) vs 复制 (Copy)

这是初学者最容易崩溃的地方。看这个例子：

```rust
let s1 = String::from("hello");
let s2 = s1; // 发生了什么？
// println!("{}", s1); // 编译报错！
```

### 为什么会报错？
在 C++ 中，这通常是浅拷贝 (Shallow Copy)。在 Python/Java 中，这是引用赋值。
但在 Rust 中，这叫 **移动 (Move)**。

- **Move (搬家)**: `s1` 是数据的所有者。当 `let s2 = s1` 发生时，`s1` 把所有权**移交**给了 `s2`。
- **后果**: `s1` 变成了废纸（无效变量）。Rust 为了防止 **Double Free (二次释放)** 错误（即 `s1` 和 `s2` 离开作用域时尝试释放同一块内存），强制废弃了 `s1`。

> **图解**:
> 想象这块内存是一张“房产证”。`s1` 手里拿着房产证。`let s2 = s1` 意味着 `s1` 把房产证递给了 `s2`。现在 `s1` 手里是空的，他不能再处理这套房子了。

## 4. 借用 (Borrowing)

如果我只是想让别人看一眼我的房产证，不想把房子送给他，怎么办？
这就是 **引用 (References)** 与 **借用 (Borrowing)**。

```rust
let s1 = String::from("hello");
let len = calculate_length(&s1); // 传递引用
println!("The length of '{}' is {}.", s1, len); // s1 依然有效！
```

### 借用规则 (The Rules of Borrowing)
这就像现实生活中的借东西：

1.  **不可变借用 (Immutable Borrow)** `&T`:
    - 你可以借给无数人看（读）。
    - 没人能修改它。
    - *类比：图书馆的公共阅览书，大家都能看，谁也不能涂改。*

2.  **可变借用 (Mutable Borrow)** `&mut T`:
    - 同一时间，只能借给一个人修改。
    - 借出去修改的时候，原来的主人也不能动它，也不能再借给别人看。
    - *类比：这书我借给你拿回家去写笔记，在我拿回来之前，其他人都看不了，我也看不了。*

> **数据竞争 (Data Race) 的克星**:
> 这个规则在编译期就根除了数据竞争。数据竞争发生的前提是：多个指针同时访问同一数据，且至少有一个在写入。Rust 的规则（多读 OR 单写）完美避开了这个条件。
