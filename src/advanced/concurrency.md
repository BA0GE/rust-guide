# 并发编程 (Concurrency)

Rust 的并发口号是：**Fearless Concurrency (无畏并发)**。

## 1. 为什么并发很难？
在 C++/Java 中，并发最大的痛点是 **数据竞争 (Data Race)**。
当两个线程同时访问同一块内存，且至少有一个在写入时，就会发生未定义行为。调试这种 Bug 是地狱级的，因为它们通常只在极低概率下复现。

## 2. Send 和 Sync Trait

Rust 将并发安全性集成到了类型系统中。这是通过两个特殊的标记 Trait 实现的：

- **`Send`**: 允许所有权在线程间转移。
    - 绝大多数类型都是 Send 的。
    - 例外：`Rc<T>` (引用计数指针) 不是 Send，因为它的计数器更新不是原子的。如果你试图把 `Rc` 传给另一个线程，编译器会报错。

- **`Sync`**: 允许被多个线程同时访问（即 `&T` 是 Send 的）。
    - `Mutex<T>` 是 Sync 的。
    - `RefCell<T>` 不是 Sync 的，因为它没有实现线程安全的借用检查。

## 3. 互斥锁 (Mutex) 的所有权哲学

在其他语言中，Mutex 只是一个锁，它保护什么数据完全靠程序员自觉。
但在 Rust 中，`Mutex<T>` 是一个**容器**，它**拥有**数据 `T`。

```rust
use std::sync::Mutex;

let m = Mutex::new(5); // 锁里包着数据

{
    let mut num = m.lock().unwrap(); // 获取锁，才能拿到数据的引用
    *num = 6;
} // 离开作用域，锁自动释放！
```

- **强制加锁**：你要访问数据，必须先调用 `lock()`。如果不加锁，你连数据的皮都摸不到（类型系统限制）。
- **自动解锁**：利用 RAII，当 `num` (MutexGuard) 离开作用域时，锁自动释放。你永远不会忘记解锁。
